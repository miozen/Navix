> 本文件记录业务与架构决策的**状态与依据**，不重复架构细节或实施步骤。架构现状见 [`ARCHITECTURE.md`](ARCHITECTURE.md)，阶段计划见 [`CURRENT_PLAN.md`](CURRENT_PLAN.md)。

状态含义：

- **Proposed**：待确认，不得据此改变既有行为。
- **Accepted**：已确认，AI 不得擅自推翻。
- **Superseded**：已被后续决策替代，仅保留历史。

变更 `Accepted` 决策时，必须先提出新的 `Proposed`/`Superseded` 条目并获得用户明确确认。

## D-001 — 保持轻量无构建架构

- **状态**：Accepted
- **决策内容**：保持原生 HTML/CSS/JS 单页与单一配置对象的轻量形态；不引入前端框架、传统数据库或复杂构建链。运行形态按 D-009 从 Pages Functions 演进为 Workers + Static Assets + KV，但“轻量、零构建、无框架”原则不变。
- **理由**：稳定、易用、不扩大产品范围；当前规模不需要更重的运行时或工具链。
- **依据**：`README.md:8,25-49`；`index.html:1-15,387-1155`；`functions/api/config.js`。
- **关系**：迁移完成前现网仍为 Pages；目标运行形态见 D-009。

## D-002 — 唯一配置入口为 `/api/config`

- **理由**：避免 `custom_links` 与 `friendLinks` 双数据源；当前 UI 已全部走 `/api/config`。

## D-007 — 修复配置接口敏感信息泄露

## D-010 — 管理员密码迁移与私有哈希存储

- **状态**：Superseded
- **决策内容**：不复用任何已经通过公开 API 暴露的旧管理员密码。迁移时重新设置密码；私有存储只保存密码哈希，不保存明文或可逆凭据；旧 localStorage Token 与旧明文密码彻底废弃。
- **理由**：旧密码已通过 `GET /api/config` 公开，继续复用等于保留已泄露凭据。
- **依据**：`functions/api/config.js:34-39`；用户四项修正第 1 条；替代 D-004。
- **实施约束**：P0 中建立一次性重新设置密码流程；应急恢复只能写入新哈希，不得回填旧密码。
- **替代决策**：D-015。保留"不复用已泄露旧密码 admin888、存储只用哈希、废弃旧 Token"三条原则；"禁止公开初始密码"一条被 D-015 的有默认初始密码 + 首次强制改密方案替代。

## D-011 — 版本检测为尽力而为的冲突提示

- **状态**：Accepted
- **决策内容**：`version` / `updatedAt` 仅用于尽力而为的冲突提示；不保证原子性，不要求检测全部并发冲突；底层 KV 读写仍按最后写入者胜出处理。
- **理由**：Cloudflare KV 的 get/put 不构成原子乐观锁，不应向用户承诺强一致性保证。
- **依据**：用户四项修正第 2 条；`functions/api/config.js:52-57`。
- **实施约束**：P1 中 UI 文案使用“可能已被其他设备更新，请刷新确认”，禁止宣称“防止覆盖”。

## D-012 — 会话 sessionVersion 失效机制

- **状态**：Accepted
- **决策内容**：管理员会话携带 `sessionVersion`；密码修改或主动吊销时递增服务端版本使旧会话失效。必须明确：受 KV 最终一致性影响，失效可能存在短暂延迟，不能承诺即时全局失效。
- **理由**：在不引入额外有状态服务的免费架构下，需要明确的失效语义与延迟说明。
- **依据**：用户四项修正第 3 条；D-010。
- **实施约束**：P0 中记录延迟边界；退出登录与改密后立即清除本地会话并提示可能需要重试。

## D-013 — 生产回退版本安全兼容

- **状态**：Accepted
- **决策内容**：生产回退版本必须兼容新数据结构与新鉴权方式；不允许回退到存在公开密码漏洞的旧版本。回退目标只能是已修复漏洞的构建产物。
- **理由**：避免通过回退重新引入已确认的严重安全漏洞。

## D-015 — 内置默认密码与首次强制改密

- **状态**：Accepted
- **决策内容**：采用公开的内置初始密码 `navix666` 作为全新部署的初始凭据。KV 无 `admin_auth` 时该默认凭据生效；首次登录返回 `mustChangePassword`，在未改密前拒绝一切配置写入（403）；用户改密后写入真实哈希到 KV，默认密码随即失效。不复用已泄露的旧密码 `admin888`；存储仍只保存哈希，不保存明文。
- **理由**：用户认为本站非保密站点，公开初始密码 + 强制首次改密即可满足需求，可免去部署时手动生成并写入密码哈希的步骤。强制改密堵住了"公开初始密码被他人抢先利用"的窗口。
- **依据**：用户明确确认（2026-11-24），并确认密码值为 `navix666`；替代 D-010 中"禁止公开初始密码"一条。
- **关系**：替代 D-010（部分）；保留其"不复用 admin888、只存哈希、废弃旧 Token"原则；与 D-007（公开响应不含凭据）、D-012（sessionVersion 失效）不冲突。
- **实施约束**：
  - 默认凭据哈希内置于 `src/lib/config.mjs`，`isDefault` 标记仅存在于内存，绝不写入 KV。
  - 首次改密要求旧密码为 `navix666`、新密码至少 8 位；改密后 `sessionVersion` 递增使旧会话失效（D-012）。
  - README 明确写出初始密码与"首次登录必须改密"的操作步骤。
  - 若 KV 中 `admin_auth` 被删除，默认密码会再次生效——文档中作为应急恢复方式说明。

## D-016 — 站点外观配置可视化与搜索引擎自定义

- **状态**：Accepted
- **决策内容**：把原先写死在前端代码里的站点名称、页脚文字、搜索引擎列表改为后台可视化配置，存于 `site_config`（沿用 D-002 唯一配置入口）。搜索引擎支持自定义名称、URL 模板（含 `{q}` 占位符）与设为默认。配置项仅管理员可改（`admin-only`）。同时为分区链接与友链增加悬停编辑入口，并修正夜间模式下链接标识的文字对比度。
- **理由**：用户希望常用外观设置不再需要改代码；网址目前只能删了重建，缺少编辑能力；夜间模式下链接标识偏暗难辨。
- **依据**：用户明确确认（2026-11-24），含"登录后可设置""搜索引擎可自定义 URL 模板""编辑用悬停按钮"三项选择。
- **关系**：在 D-002（唯一配置入口 `site_config`）范围内扩展字段；不改变 D-001 轻量无构建原则；与 D-007（公开响应不含凭据）不冲突。
- **实施约束**：
  - 服务端 `PUBLIC_KEYS` / `ALLOWED_KEYS` 增加 `siteTitle`、`footerText`、`engines` 三个字段并做长度/结构校验。
  - 前端保留默认值兜底，云端无这些字段时用原写死值，保证平滑升级。
  - 搜索引擎 URL 模板必须含 `{q}` 且为 http(s)，非法输入被服务端拒绝。
  - 站点设置 UI 使用 `admin-only`，普通访客不可见/不可改。
